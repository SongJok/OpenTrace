# 记忆宪法

OpenTrace 的记忆宪法是工作区级、版本化且实时读取的记忆治理策略。管理员在“权限与记忆治理 → 记忆宪法”发布新版本后，新写入立即使用该版本；现有活动记忆会同步复核，召回链路还会再次校验。

发布前可执行“影响预览”，系统只返回扫描数量、预计隔离数量以及原因和类别聚合，不返回记忆原文，也不会修改任何数据。发布请求携带管理员打开页面时看到的版本号；如果另一位管理员已先发布，旧页面会收到冲突提示，必须刷新后再确认，避免无提示覆盖。

## 两层约束

第一层是不可削弱的安全底线，始终禁止保存认证秘密、身份号码、支付账户、第三方个人信息，以及要求绕过系统规则或隐藏记忆的指令。

第二层由管理员配置，可调整健康、财务画像、联系方式、精确位置、短期信息等类别，主动学习的允许类型、最低置信度、重复观察次数、单条长度和保留期限。管理员也可设置确定性禁用词；宪法正文中的 `禁止记忆词：词语A、词语B` 同样会被实时解析。

## 覆盖入口

- Response 完成后的主动学习和显式“记住”学习；
- 记忆页面的手工新增与内容修改；
- 记忆候选的人工批准；
- Manager Context 与 RagAgent 的记忆召回。

被拦截的内容不会进入用户记忆。审计表只保存原因、类别和内容哈希，不保存被拦截的原始敏感文本。模型提取的候选始终进入人工确认；确定性主动候选可通过工作区设置要求多次独立观察后再自动激活。

每次有效发布都会生成只读历史版本；重复发布完全相同的内容不会产生空版本。管理员可以从历史记录恢复策略，恢复操作会基于旧内容创建一个新的活动版本，旧记录本身保持不变。数据库同时约束每个租户与工作区最多只有一个活动版本。

## 设计依据

该机制采用可选记忆、用户控制、临时会话不学习、敏感信息谨慎处理、数据最小化、生命周期治理、策略版本与持续治理等原则。安全底线由代码强制执行，管理员只能在其上增加限制。
