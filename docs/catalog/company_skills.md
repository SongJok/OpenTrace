# 公司 Skills

公司 Skill 是由企业在 OpenTrace 之外从线上代码和业务资料中预先蒸馏、审核完成的静态业务语义包。它与 RAG、企业大脑、个人记忆和数据库并列进入 Responses 主路径，但职责不同：

- 公司 Skill：解释业务过程、表结构、字段含义、核心代码注释、口径和判断规则；
- RAG：提供已发布文档证据和引用；
- 企业大脑：提供公司及部门认知和稳定企业事实；
- 个人记忆：提供当前用户范围内的偏好与已确认背景；
- DataAgent：基于受治理数据库生成、确认并执行查询，返回实时或历史数据事实。

## 上传契约

管理员在 Skills 页面上传一个 `SKILL.md` 或包含它的文件夹。项目不会调用模型再次蒸馏，也不会执行包内代码、命令、宏或外部链接。

`SKILL.md` 必须是 UTF-8 文本。上传完整文件夹时，文件夹名是公司 Skill 的发布名称；YAML
frontmatter 可选，没有时系统仅提取一级标题后的首段作为列表摘要，不改写正文，也不调用模型。
只上传单个 `SKILL.md` 时应提供 frontmatter 中的 `name`，以便确定发布名称：

```yaml
---
name: 订单线上业务字典
description: 解释订单流程、表结构和字段业务逻辑。
version: 1.0.0
use_cases:
  - 回答订单状态和字段口径
---
```

包内可携带 Markdown、SQL、CSV/TSV、JSON/YAML 和常见源码纯文本文件。单文件最大 2MB，整个包最大 12MB，最多 80 个文件；路径穿越、隐藏目录、二进制内容和检测到的私钥/密钥会被拒绝，macOS/Windows 自动生成的 `.DS_Store`、`Thumbs.db` 和 `__MACOSX` 元数据会被忽略。文件内容和摘要持久化到 PostgreSQL，同时投影到 API/Worker 共享本地镜像；列表接口只返回来源元数据，不返回企业 Skill 原文。所有包均固定为 `context_only`：reference 中即使包含 Python、Shell 或 SQL，也只参与文本检索，平台永不加载或执行。

## 问答与冲突规则

`ContextAssembler` 在完整的 user、tenant、workspace 和密级范围内检索已发布公司 Skill，只注入与当前问题最相关的片段。命中内容已经明确表、字段或流程时，Manager 应直接回答，不要求用户重复确认；存在会实质改变答案的缺失条件、来源冲突或写/破坏性动作时仍需澄清或审批。

公司 Skill 是静态实现语义，不代表数据库当前记录。实时金额、状态和数量必须来自 DataAgent 实际查询；若 Skill 与当前数据库结构冲突，应明确版本差异并以数据库可验证结构为准。上传内容不能覆盖平台权限、租户隔离、审批、安全规则或当前用户指令。

## 生命周期与审计

上传、重新发布和移除都按租户/工作区隔离并记录审计。移除采用归档语义：立即停止进入问答上下文，但保留数据库记录和本地不可变镜像，后续上传相同包可重新发布。历史上由项目主动蒸馏的已发布记录继续只读兼容；主动蒸馏 API 和页面入口已经移除。
