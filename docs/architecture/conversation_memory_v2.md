# 多轮对话与记忆连续性设计 V2

## 目标

OpenTrace 的在线对话继续以 Responses API、PostgreSQL Response 父链和 Agent Worker 为唯一主路径。
本设计不引入第二套会话事实来源，重点提升长对话连续性、用户纠错后的记忆一致性，以及提问主链要求的隔离和可恢复性。

## 三层连续性模型

### 短期工作上下文

- 只读取当前 Response 的父链，保留最近完整用户回合、助手回答、工具调用和工具结果。
- 父链节点必须同时匹配 `user_id`、`tenant_id`、`workspace_id` 和 `conversation_id`；任一边界不一致立即停止读取。
- 当前消息和后来的用户更正始终高于历史消息、摘要与长期记忆。
- 写操作只有持久化审批和工具账本能够证明完成，历史中的提议或待审批调用不能被表述为已完成。

### 中期会话检查点

- 长分支达到阈值后，由压缩模型生成结构化检查点，而不是不可解释的自由文本摘要。
- 检查点包含当前目标、有效约束、已确认决定、未完成事项、已确认事实、工具证据和最近关键回合。
- 摘要输入包含用户/助手消息、工具调用与工具结果，并记录来源 Response、校验和、版本和 token 数。
- 新检查点继承上一版仍有效状态；用户后来的更正覆盖旧说法。
- 若供应商未返回合法结构，保留自由文本兼容结果，不阻断主回答。

### 长期受治理记忆

- 只学习稳定、低风险且有 Response/Item 证据的信息；临时会话、禁用记忆模式和记忆宪法继续作为硬边界。
- 一条消息可以确定性提取多项稳定信息；姓名、职责、回答偏好、个人术语、审批习惯、常用模板、工作时间和 Project 约定使用稳定 key，并按 user/project/conversation scope 写入。
- 同一内容被不同 Response 重复确认时复用原候选和 `UserMemory` 节点，累计观察次数、置信度、显著性和证据；同一 Response 重试不重复计数。
- 用户以“更正、现在改为、不是旧值而是新值”等方式明确修正稳定个人事实时，新记忆以 `correction` 学习模式激活并替代同 scope、同 key 的旧记忆。
- 用户具名要求“忘记我的某项信息”时，只在当前有效 scope 内失效精确主题匹配的活动记忆和待确认候选，并保留触发 Response/Item 证据；模糊的全量删除继续要求在记忆管理页显式执行。
- “不要记住”“仅这一次”等否定或临时表达不能产生记忆候选，也不能被模型补充提取重新写回。
- 更正不会自动置顶；只有用户明确要求“记住”的信息保持 pinned 语义。
- 记忆读取继续限定 user、tenant、workspace，并按 user/project/conversation scope 隔离。
- 任务和审批状态不复制为长期语义记忆；当前业务表是事实来源，历史状态仅按用户明确的问题
  召回。稳定偏好和重复习惯仍可长期学习。

## 失败与恢复语义

- 摘要和记忆学习均在 Response 正文完成后执行，失败只记录告警，不把已完成回答回滚为失败。
- PostgreSQL 仍是 Response、Item、Event、摘要、候选、证据和长期记忆的事实来源。
- 结构化检查点带版本与来源校验和，可审计每次压缩覆盖的父链范围。
- 已被替代的记忆保留记录并标记为 `superseded`，而不是物理删除。

## 验收标准

- 能准确处理“上一轮、前面、那个方案、继续、改成”等跨轮表达。
- 长对话裁剪后仍保留目标、约束、决定、未完成事项和工具执行状态。
- 用户明确纠正旧事实后只召回新值，旧值可审计但不可继续参与回答。
- 重复陈述只强化同一记忆节点；具名遗忘后该记忆立即停止跨会话召回，相近但不同的主题不受影响。
- 篡改或错误关联的跨用户、跨租户、跨工作区父链不会进入模型上下文或摘要。
- 后端完整测试、vNext 主路径、导入边界、前端测试与生产构建均通过。
