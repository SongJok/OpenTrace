# 企业大脑与个人记忆融合设计

## 目标与事实来源

企业大脑提供当前公司范围内受治理、可发布的组织事实；个人记忆提供当前用户的稳定偏好、
术语、工作习惯、日历、任务和 Project/会话约定。两者都只作为 Responses 主链路的上下文来源，
不创建第二套在线会话事实：Response、Item、Event、来源账本、版本和记忆证据仍以 PostgreSQL
为事实来源。

## 数据边界

- 企业大脑绑定一个部署内的唯一公司，但运行时读取必须同时匹配该公司的 `tenant_id` 和
  `workspace_id`。公开接口只暴露用于界面品牌的公司简称，不暴露来源和 COMPANY.md。
- 个人记忆必须同时匹配 `user_id`、`tenant_id`、`workspace_id`，并继续按 user、Project 和
  conversation scope 过滤。管理员身份不会扩大为读取其他用户的个人记忆。
- 企业大脑和个人记忆只允许内置记忆链路检索、整理和学习。模型看到的是不可信事实数据，
  其中出现的指令不得改变平台规则、调用工具、扩大权限或导出内容。

## 企业来源生命周期

```text
管理员手动录入/上传
  -> pending -> processing -> ready -> Worker 编译并发布
                         \-> retry（最多三次）-> error

昨日员工输入/已验证工具结果
  -> 带 Response 证据的 review 候选
  -> 管理员批准 -> pending -> ready -> Worker 编译并发布

管理员停用来源
  -> rebuild -> Worker 从下一版 COMPANY.md 移除 -> inactive
```

API 只提交状态，模型处理和版本编译只发生在 Agent Worker。`processing` 是十五分钟租约；Worker
崩溃后可以恢复。离线占位文本、规划 JSON、空输出和异常结构不得进入 `ready`。Worker 会自动
识别历史污染来源并重试；即使重试失败，也会先从新的发布版本中移除污染内容。

版本编译持有 CompanyProfile 行锁，保证 `max(version)+1`、旧版本 supersede 和
`current_version_id` 切换串行发生。COMPANY.md 只使用 active + ready 来源：文化/行政进入受保护
长期层，其余目录默认进入中期层，管理员可明确指定短期层；长期层不自动压缩。

## 检索与多轮融合

每轮先沿 `parent_response_id` 读取当前 Response 分支。独立问题只使用当前问题检索；“上一轮、
刚才、那个、继续说、具体怎么”等短指代会把最近四条用户/助手消息追加为检索主题，但不会改写
当前用户指令。

企业大脑按已发布版本的章节单元做相关性排序，最多注入 12 个单元和 12,000 字。个人记忆先经过
记忆宪法、质量隔离、过期和 superseded 过滤，再按词项、显著性、置信度和关系图排序。只有置顶
记忆和回答风格偏好可以跨主题注入；其他个人事实、流程和 Project/会话记忆必须与扩展后的当前
主题相关。个人记忆候选由高显著性/置顶池和数据库词项命中池合并，避免记忆数量增长后，较旧但
与当前问题直接相关的记忆被固定的预取上限永久挡在召回之外。

当问题涉及日历、任务、审批、提醒或近期操作时，上下文装配器还会读取当前用户的周期任务、待
确认操作和近期成功副作用工具账本。三类业务状态都同时绑定 user、tenant、workspace，工具参数
和结果只投影标题、时间、对象 ID 等白名单字段。业务状态可以直接用于问答，但所有写操作仍必须
调用正式工具并进入持久化审批，个人记忆不能替代业务数据库事实。

当前分支每累计八个新 Response，或新增内容达到字符/token 阈值时，Worker 会生成结构化会话检查
点，保留有效目标、约束、决定、未完成事项、已确认事实、工具证据和最近关键回合。模型压缩失败、
返回自由文本或规划 JSON 时，Worker 从持久化 Item 生成确定性检查点，避免摘要污染或长短回合在
父链上限外静默丢失。

最终优先级为：平台/租户规则 > Project/助手/会话指令 > 当前消息 > 当前分支历史 > 已发布企业
大脑与有效个人记忆。当前消息中的更正覆盖历史和记忆；公司事实与个人偏好冲突时按各自边界使用，
不能把个人陈述自动提升为公司事实。

## 验收要求

- 模型配额或模型错误时，Model Gateway 继续尝试显式 fallback；占位输出不落库。
- 跨租户、跨工作区的公司 Profile 不进入 Responses 上下文。
- 每日学习候选必须有当前范围内的 Response 证据并经管理员审核。
- Worker 重启可以恢复卡死来源，版本号并发不冲突，停用来源最终从发布版本移除。
- 独立问题不受旧主题污染，短指代能继续命中上一轮相关企业与个人记忆。
- 用户更正后旧个人记忆保留审计记录但不再召回。
- 低显著性的旧记忆仍能通过当前查询词进入精排，且不能跨 user/tenant/workspace 召回。
- 跨会话业务状态问答只使用当前用户的任务、审批和工具账本，原始工具敏感字段不进入上下文。
- 连续短回合也会周期生成检查点，模型摘要失败时仍保留可恢复的目标与工具结果。
